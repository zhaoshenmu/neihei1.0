# 📦 节点系统设计

## 一、节点类型一览（6种）

| 节点 | 图标 | 用途 | 颜色 | 是否必须 |
|------|------|------|------|---------|
| **Idea** | 💡 | 用户想法/灵感输入 | 白色 | 否 |
| **Kernel** | ⚙️ | 记忆+防幻觉引擎（唯一核心） | 金色 | **是** |
| **LLM** | 🤖 | 调用AI生成 | 蓝色 | 否 |
| **Edit** | ✏️ | 人工干预节点 | 绿色 | 否 |
| **Output** | 📦 | 插件化输出容器 | 橙色 | 否 |
| **Plugin** | 🧩 | 通用扩展（复用 chajian/） | 灰色 | 否 |

## 二、节点详细设计

### 2.1 💡 Idea 节点

```
┌─────────────────────────┐
│ 💡 用户想法              │
│ ┌─────────────────────┐ │
│ │ 主角是林夜，一个被    │ │
│ │ 灭门的少年，意外获得  │ │
│ │ 神秘古玉...          │ │
│ └─────────────────────┘ │
│ 输出端口:                │
│ ● raw_idea (文本)       │
│ ● seed_triples (三元组)  │
└─────────────────────────┘
```

**功能**：
- 输入零散想法或创意
- 自动提取种子三元组（基于简单NLP或LLM辅助）
- 可以保存多个想法版本

### 2.2 ⚙️ Kernel 节点

```
┌─────────────────────────────────────┐
│ ⚙️ Kernel              [🟢 运行中]  │
├─────────────────────────────────────┤
│ 记忆层: 42条 | 约束: 12条           │
│ 最近检测: ✅ 通过                    │
├─────────────────────────────────────┤
│ 输入端口:                            │
│ ● text_in (文本输入)                │
│ ● triples_in (三元组输入)           │
│ ● feedback (用户反馈)               │
│ 输出端口:                            │
│ ● text_out (增强后文本)             │
│ ● validated (已验证输出)            │
│ ● triples_out (更新后三元组)        │
└─────────────────────────────────────┘
```

**功能**：参见 `02-内核架构.md` 完整说明。

**双击行为**：打开内核控制面板（6标签）。

### 2.3 🤖 LLM 节点

```
┌─────────────────────────────┐
│ 🤖 LLM · LM Studio          │ ← 下拉选择适配器
├─────────────────────────────┤
│ 模型: qwen2.5-14b           │ ← 下拉选择模型
│ 温度: 0.8      max: 4096   │ ← 参数调节
│                             │
│ 输入端口:                    │
│ ● prompt (提示词)           │
│ ● context (上下文)          │
│ ● inject (约束注入)         │
│ 输出端口:                    │
│ ● response (LLM响应)        │
│ ● raw_triples (原始三元组)   │
└─────────────────────────────┘
```

**功能**：
- 调用 LLM 生成文本
- 支持多适配器：LM Studio / OpenAI / Claude
- 支持参数调节（温度、max_tokens、top_p 等）
- 可以设置多个 LLM 节点并行（多LLM协作模式）

**适配器接口**：

```typescript
interface LLMAdapter {
  name: string;
  models: string[];                    // 可用模型列表
  generate(params: LLMRequest): Promise<LLMResponse>;
}

interface LLMRequest {
  model: string;
  messages: { role: string; content: string }[];
  temperature?: number;
  maxTokens?: number;
}

interface LLMResponse {
  content: string;
  usage: { promptTokens: number; completionTokens: number };
}
```

### 2.5 📦 Output 节点

```
┌──────────────────────────────────────┐
│ 📦 Output                            │
│                                      │
│ 选择的输出插件: [三元图谱 ▼]         │
│                                      │
│ ┌──────────────────────────────────┐ │

│ │ ┌──────┐                         │ │

│ │ └──────┘                         │ │

│ 输入端口:                             │
```

**功能**：
- 不内置任何渲染逻辑
- 从 `chajian/` 自动扫描可选输出插件
- 用户在节点内下拉选择输出格式
- 支持同时连接多个 Output 节点（多格式输出）

**输出插件列表**（位于 chajian/）：

| TimelineView | 📅 时间线 | 事件按时间排列 |
| JSONExporter | 💾 JSON | 导出为JSON文件 |

## 三、端口颜色编码规范

每个节点的端口遵循统一颜色编码：

| 端口类型 | 颜色 | 数据内容 | 示例 |
|---------|------|---------|------|
| ● **文本** | 白色 | 故事文本、章节内容 | Idea的raw_idea |
| ● **三元组** | 金色 | 实体、关系、置信度 | Kernel的triples_out |
| ● **配置** | 蓝色 | 提示词、参数、约束 | LLM的prompt |
| ● **控制** | 红色 | 触发、停止、条件 | Edit的cmd |
| ● **状态** | 绿色 | 日志、进度、指标 | Kernel的validated |

**连线规则**：
- 同色端口可以直接相连
- 不同色端口相连时自动转换（显示转换箭头图标）
- 不支持的连接组合显示红色禁止符号

## 四、5种工作流模式

### 模式A：全自动（一条直线）

```
💡 Idea ──► ⚙️ Kernel ──► 🤖 LLM ──► ⚙️ Kernel ──► 📦 Output
```

适合：快速生成，无需干预。

### 模式B：半自动（人工介入关键点）

```
💡 Idea ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ⚙️ Kernel ──► ✏️ Edit ──► 📦 Output
```

适合：你想控制提示词和审查结果。

### 模式C：全手动（每步都控）

```
💡 Idea ──► ✏️ Edit ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ✏️ Edit ──► ⚙️ Kernel ──► 📦 Output
```

适合：精调每一步，最大化可控性。

### 模式D：多LLM协作

```
💡 Idea ──► ⚙️ Kernel ──outline──► 🤖 LLM A (大纲)
                            │
                            └──chapter──► 🤖 LLM B (正文) ──► ✏️ Edit ──► 📦 Output
                            │
                            └──review──► 🤖 LLM C (审校)
```

适合：不同任务用不同模型（如Claude写大纲，本地模型写正文）。

### 模式E：分支合并

```
💡 Idea ──► ⚙️ Kernel
                │
        ┌───────┼───────┐
        ▼       ▼       ▼
    🤖 LLM   🤖 LLM   🤖 LLM
    (主角)   (反派)   (旁观者)
        │       │       │
        └───► ✏️ Edit (合并)
                    │
                    ▼
               📦 Output
```

适合：多视角写作，合并成多线叙事。

## 五、输出插件化机制

### 5.1 插件接口

```typescript
// chajian/ 下的每个输出插件必须实现：
interface OutputPlugin {
  id: string;
  name: string;
  icon: string;
  description: string;
  
  // 接受的数据类型
  accepts: ('text' | 'triples' | 'both')[];
  
  // 渲染函数
  render(data: OutputData): React.ReactNode;
  
  // 导出函数（可选）
  export?: (data: OutputData) => Blob;
}

interface OutputData {
  text?: string;
  triples?: Triple[];
  metadata?: {
    chapterId?: number;
    timestamp?: number;
    source?: string;
  };
}
```

### 5.2 插件发现机制

利用现有的 `chajian/index.ts` + `plugin-loader.ts`：

```typescript
// chajian/index.ts
export { default as NovelGenerator } from './NovelGenerator';
export { default as ScriptGenerator } from './ScriptGenerator';
export { default as GraphVisualizer } from './GraphVisualizer';
export { default as ChartGenerator } from './ChartGenerator';
// 用户加新输出插件只需加一行：
// export { default as MyPlugin } from './MyPlugin';

// Output 节点启动时：
const availablePlugins = scanOutputPlugins(); // 从 chajian/ 扫描
// 用户在下拉列表中选一个
```

### 5.3 图谱可视化插件（特殊地位）

GraphVisualizer 插件与其他插件不同——它不在 Output 节点内渲染，而是**直接在画布上创建图谱层节点**：

```
Output 节点选择「三元图谱」→ 触发 GraphVisualizer →
GraphVisualizer 从内核 TripleStore 读取数据 →
在画布上生成一组图谱节点 + 连线 →
用户可以在画布上拖拽、缩放、点击查看详情
```

这意味着**图谱和输出是同一数据的不同视图**，而非额外工具。

## 六、节点间数据包格式

节点之间传递的数据使用统一的数据包格式：

```typescript
interface NodeDataPacket {
  id: string;
  sourceNodeId: string;
  targetNodeId: string;
  portType: 'text' | 'triples' | 'config' | 'control' | 'status';
  
  // 根据 portType 填充对应字段
  text?: string;
  triples?: Triple[];
  config?: Record<string, any>;
  control?: { command: string; payload?: any };
  status?: { level: 'info' | 'warn' | 'error'; message: string };
  
  metadata: {
    timestamp: number;
    chapterId?: number;
    sequence: number;       // 工作流执行序号
    trace: string[];        // 经过的节点路径
  };
}
```

数据包在内核中经过时，会被附加约束验证结果和记忆上下文，确保每个下游节点都拥有完整的信息。
