# 📦 节点系统设计

## 一、节点类型一览（13种）

| 节点 | 图标 | 用途 | 颜色 | 是否必须 |
|------|------|------|------|---------|
| **Idea** | 💡 | 用户想法/灵感输入 | 白色 | 否 |
| **Outline** | 📋 | 结构化大纲模板（世界观/人物/红线/卷大纲/锚点） | 蓝色 | 否 |
| **Kernel** | ⚙️ | 记忆+防幻觉引擎（唯一核心） | 金色 | **是** |
| **LLM** | 🤖 | 调用AI生成 | 蓝色 | 否 |
| **Edit** | ✏️ | 人工校对节点 | 绿色 | 否 |
| **Prompt** | 📝 | 结构化记忆→自然语言翻译 | 紫色 | 否 |
| **Refine** | 🦴 | 全文→骨架三元组精炼 | 灰色 | 否 |
| **Format** | 📊 | 三元组→表格/图谱/JSON转换 | 灰色 | 否 |
| **Loop** | 🔄 | 故事弧循环控制 | 紫色 | 否 |
| **Output** | 📦 | 插件化输出容器 | 橙色 | 否 |
| **Plugin** | 🧩 | 通用扩展（复用 chajian/） | 灰色 | 否 |
| **Storage** | 🗄️ | 持久化存档柜（监听事件，不连线） | 灰色 | 否 |
| **Graph** | 🕸️ | 图谱可视化（只读视图） | 金色边 | 否 |

## 二、节点详细设计

### 2.2 📋 Outline 节点（大纲模板）

```
┌──────────────────────────────────────────────────────────┐
│ 📋 大纲编辑器              [⚡ 活跃 - 注入约束闸门]       │
├──────────────────────────────────────────────────────────┤
│                                                          │
│ ┌─ 【世界观】 ──────────────────────────────────────────┐│
│ │ 时代背景: 玄幻-修仙界                                 ││
│ │ 世界规则: 练气→筑基→金丹→元婴，不可逆天改命           ││
│ │ 核心基调: 爽文 + 热血                                ││
│ │ 故事主题: 逆袭 + 复仇                                ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ┌─ 【主线】 ───────────────────────────────────────────┐│
│ │ 主角终极目标: 手刃灭门仇人，登顶修仙界                ││
│ │ 最终反派: 天玄宗长老                                  ││
│ │ 结局方向: HE - 主角达成目标，与爱人相守               ││
│ │ 总节奏: 前10章慢热，后续中速推进                      ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ┌─ 【人物】 ───────────────────────────────────────────┐│
│ │ 主角: 林夜 / 外冷内热 / 复仇 / 信任困难 / 青冥剑     ││
│ │ 配角: 慕容雪 / 立场中立 / 亦师亦友 / 指导修炼        ││
│ │ 反派: 陈玄机 / 嫉妒主角天赋 / 幻术 / 被废修为        ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ┌─ 【卷大纲】 ──── 配置 Loop ──────────────────────────┐│
│ │ 第1卷: 入门篇 (1-10章)                               ││
│ │ 第2卷: 成长篇 (11-25章)                              ││
│ │ 第3卷: 决战篇 (26-40章)                              ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ┌─ 【章节锚点】 ── 当前第2卷/第8章 ───────────────────┐│
│ │ 本章目的: 林夜参加宗门大比                            ││
│ │ 关键事件: 展露实力，引反派嫉妒                       ││
│ │ 结束状态: 林夜进入决赛                               ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ┌─ 【红线规则】 ──────────────────────── [🔴 绝对约束] ┐│
│ │ ❌ 不能写死: 林夜、慕容雪                             ││
│ │ ❌ 不能推翻: 修仙界需渡劫飞升                         ││
│ │ ❌ 不能OOC: 林夜不可突然残忍嗜杀                      ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ [📤 激活] [💾 保存大纲模板] [📥 加载已有大纲]          │
└──────────────────────────────────────────────────────────┘
```

**六个板块的流向**：

| 板块 | 流向 | 说明 |
|------|------|------|
| **【世界观】** | → 约束闸门（ConstraintEngine） | 每次 LLM 调用强制注入，**不入洋葱层** |
| **【主线】** | → 约束闸门 + Loop 配置 | 目标决定何时停止循环 |
| **【人物】** | → 约束闸门 | 角色约束 + 防止 OOC |
| **【卷大纲】** | → 配置 🔄 Loop 节点 | 决定总卷数、每卷章数 |
| **【章节锚点】** | → 📝 Prompt 节点 + Layer 2 | 每章更新，前后关联 |
| **【红线规则】** | → 约束闸门（最高优先级） | **绝对不可突破** |

**关键约束**：Outline 节点的内容**不入内核洋葱层**。世界观、人物、红线规则只进入约束闸门（ConstraintEngine），每次 LLM 调用时强制注入但不存储。换项目只需换 Outline 节点的配置文件，内核保持干净。

### 2.3 ⚙️ Kernel 节点

```
┌─────────────────────────────────────┐
│ ⚙️ Kernel              [🟢 运行中]  │
├─────────────────────────────────────┤
│ 记忆层: 42条 | 约束: 12条           │
│ 最近检测: ✅ 通过                    │
├─────────────────────────────────────┤
│ 输入端口:                            │
│ ● text_in (大纲/设定文本输入)        │ ← 来自 Idea/Outline
│ ● feedback (校对后文本输入)          │ ← 来自 Edit(校对后文章)
│ 输出端口:                            │
│ ● text_out (增强后文本→LLM)         │ ← 带前情提要的提示词
│ ● validated (验证通过→Output)       │ ← 校对后验证结果
│ ● triples_out (更新后三元组)         │ → EventBus → Graph/Storage
└─────────────────────────────────────┘
```

**功能**：参见 `02-内核架构.md` 完整说明。

**双击行为**：打开内核控制面板（4标签：记忆层 / 约束 / 检测 / 设置）。

**Kernel 在章节循环模式中的双重角色**：

| 角色 | 时机 | 输入 | 输出 | 
|------|------|------|------|
| **事前注入** | LLM 写作前 | text_in(大纲/写作指令) | text_out(带前情提要的增强文本) |
| **事后写回** | 校对完成后 | feedback(校对后文章) | validated(验证通过)+triples_out(更新记忆) |

### 2.4 📝 Prompt 节点（提示词转换）

```
┌──────────────────────────────────────┐
│ 📝 提示词翻译器                       │
├──────────────────────────────────────┤
│ 输入: 结构化三元组记忆                │
│ ↓                                     │
│ "前情提要：                           │
│  林夜目前是筑基期修为，                │
│  拥有青玄古玉，位于青城山。            │
│  请基于以上设定继续写第4章。"           │
│ ↓                                     │
│ 输出: 自然语言提示词                  │
│                                      │
│ 模板: [修仙 ▼]                        │
│ 风格: [热血 ▼]                        │
│                                      │
│ 输入端口:                             │
│ ● triples_in (来自Kernel的三元组)     │
│ 输出端口:                             │
│ ● prompt_out (自然语言提示词→LLM)     │
└──────────────────────────────────────┘
```

**功能**：
- 将内核的结构化三元组记忆翻译成 LLM 能理解的自然语言

- 只读内核数据，不写入内核

├──────────────────────────────────────┤

```
┌──────────────────────────────────────┐
│ 🔄 故事弧循环控制器                    │
├──────────────────────────────────────┤
│ 模式: [按卷数 ▼]                      │
│ 设定卷数: [5]                         │
│ 当前进度: ██████░░░░ 3/5             │
│                                      │
│ 每卷结构:                             │
│ 第1卷：1-5章 (已完成)                │
│ 第2卷：6-10章 (进行中)               │
│ 第3卷：11-15章 (待生成)              │
│                                      │
│ 循环方向：⬇ 下一卷                    │
│                                      │
│ 输入端口:                             │
│ ● trigger_in (来自Edit校对完成信号)   │
│ 输出端口:                             │
│ ● continue (继续→Kernel查记忆+注入)   │
│ ● stop (停止→Output最终出稿)          │
│                                      │
│ [▶ 继续] [⏹ 停止] [⏭ 跳过本卷]      │
└──────────────────────────────────────┘
```

**功能**：
- 控制故事弧的循环次数（不是按章循环，是按「卷/完整故事单元」循环）
- 每个完整故事单元包含：开端→发展→高潮→低谷→结束
- 到达设定卷数或用户点停止 → 输出最终全文
- 新手可视化：看得见的循环线，无需理解内核"自动注入"
- 从 📋 Outline 节点读取卷大纲配置

**适配器接口**：

```typescript

  name: string;
  models: string[];

interface LLMRequest {
  model: string;
  messages: { role: string; content: string }[];
  temperature?: number;
  maxTokens?: number;
}

interface LLMResponse {
  content: string;
  usage: { promptTokens: number; completionTokens: number };
}
```

### 2.12 🗄️ Storage 节点（持久化存档柜）

```
┌──────────────────────────────────────┐
│ 🗄️ 我的书架             [🟢 已连接]  │
├──────────────────────────────────────┤
│ 📚 仙道无双              [继续写作]   │
│    最后: 第3卷/第15章                 │
│    记忆版: v42                       │
│                                      │
│ 📚 都市潜龙              [继续写作]   │
│    最后: 第1卷/第8章                  │
│    记忆版: v18                       │
│                                      │
│ 📚 星际争霸              [新建]      │
│    状态: 大纲阶段                     │
│                                      │
│ [➕ 新建小说]                         │
├──────────────────────────────────────┤
│ 不设输入/输出端口（仅监听 EventBus）  │
└──────────────────────────────────────┘
```

**定位**：小说的**存档柜**——不需要连线，只监听内核事件。

**职责边界（严格遵守）：**
- ✅ 订阅内核 EventBus 的 `kernel:memory-updated` 事件
- ✅ 将 Layer 0-2 三元组写入 IndexedDB（长期保存）
- ✅ 页面加载时从 IndexedDB 恢复数据 → 写回内核
- ❌ 不修改三元组内容
- ❌ 不参与记忆验证
- ❌ 不渲染图谱
- ❌ 不需要与 Graph 节点连线（各自独立订阅事件）

**未来扩展 — 多小说书架**：
- 支持多本小说的存档管理
- 点击某本小说 → 恢复对应记忆版本 → 接着写
- 切换小说时 Storage 读出对应快照 → 写回 Kernel → Graph 自动恢复

**工作原理：**

```
⚙️ Kernel 完成写回
    ↓ 发出事件
EventBus: 'kernel:memory-updated'
    ↓
🗄️ Storage 节点收到事件
    ├─ 提取 layers.layer0, layer1, layer2
    ├─ 版本号比对（防乱序）
    ├─ 写入 IndexedDB（键: memory_snapshot）
    └─ 更新本地版本号

📱 用户关闭页面 → 下次打开
    ├─ Storage 节点启动时从 IndexedDB 读取
    ├─ 调用 kernel.restoreFromStorage(layers)
    └─ 内核恢复 Layer 0-1 → 发出事件 → Graph 自动更新
```

## 三、EventBus 画布通信线路

### 3.1 EventBus 不是节点，是连接所有节点的隐形中线

EventBus 是画布级的事件总线，不属于任何节点。它是内核与其他组件通信的唯一通道。

Kernel 只往 EventBus 发事件，不直接调任何外部组件。谁订阅事件，Kernel 不关心。

```
                    ┌─────────────────────────┐
                    │      EventBus            │
                    │  (画布级事件总线)         │
                    └──────────┬──────────────┘
          ┌────────────────────┼────────────────────┐
          ▼                    ▼                    ▼
    ┌──────────┐        ┌──────────┐         ┌──────────┐
    │ ⚙️ Kernel │        │ 🕸️ Graph  │         │ 🗄️ Storage │
    │ (发布者)  │        │ (订阅者)  │         │ (订阅者)  │
    └──────────┘        └──────────┘         └──────────┘
```

**关键原则**：Storage 和 Graph 之间没有连线，它们都只订阅 Kernel 的事件。

### 3.2 事件类型定义

| 事件名 | 发布者 | 订阅者 | 说明 |
|--------|-------|-------|------|
| `kernel:memory-updated` | ⚙️ Kernel | 🕸️ Graph, 🗄️ Storage, 📋 LogPanel | 记忆已更新，附只读快照 |
| `kernel:validation-result` | ⚙️ Kernel | 📋 LogPanel | 幻觉检测结果 |
| `user:request-edit` | 🕸️ Graph, ✏️ Edit | ⚙️ Kernel | 用户请求修改数据 |
| `kernel:edit-processed` | ⚙️ Kernel | 🕸️ Graph, ✏️ Edit | 用户请求已处理 |
| `storage:data-restored` | 🗄️ Storage | ⚙️ Kernel | 持久化数据已恢复 |

## 五、6种工作流模式

### 模式A：全自动（一条直线）

```
💡 Idea ──► ✏️ Edit ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ✏️ Edit ──► ⚙️ Kernel ──► 📦 Output
```

适合：快速生成，无需干预。

### 模式B：半自动（人工介入关键点）

```
💡 Idea ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ⚙️ Kernel ──► ✏️ Edit ──► 📦 Output
```

适合：你想控制提示词和审查结果。

### 模式C：全手动（每步都控）

```
💡 Idea ──► ✏️ Edit ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ✏️ Edit ──► ⚙️ Kernel ──► 📦 Output
```

适合：精调每一步，最大化可控性。

### 模式D：多LLM协作

```
💡 Idea ──► ⚙️ Kernel ──outline──► 🤖 LLM A (大纲)
                            │
                            └──chapter──► 🤖 LLM B (正文) ──► ✏️ Edit ──► 📦 Output
                            │
                            └──review──► 🤖 LLM C (审校)
```

适合：不同任务用不同模型（如Claude写大纲，本地模型写正文）。

### 模式E：分支合并

```
💡 Idea ──► ⚙️ Kernel
                │
        ┌───────┼───────┐
        ▼       ▼       ▼
    🤖 LLM   🤖 LLM   🤖 LLM
    (主角)   (反派)   (旁观者)
        │       │       │
        └───► ✏️ Edit (合并)
                    │
                    ▼
               📦 Output
```

适合：多视角写作，合并成多线叙事。

### 模式F：故事弧循环模式（完整架构）

```
💡 Idea（零散想法）
    ↓
📋 Outline（结构化大纲模板）
    ├──→ ⚙️ 约束闸门（世界观/人物/红线 → 注入但不存储）
    ├──→ 🔄 Loop（卷大纲 → 配置循环参数）
    └──→ ⚙️ Kernel Layer 2（章节锚点 → 短期记忆）
                ↓
           📝 Prompt（骨架记忆 → 自然语言翻译）
                ↓
           🤖 LLM（写第N卷：开端→发展→高潮→低谷→结束）
                ↓
           ✏️ Edit（人工校对整卷）
                ↓
           ┌── 📦 Output（本卷出稿）
           │
           🦴 Refine（整卷全文 → 骨架三元组）
                ↓
           ⚙️ Kernel 更新（验幻觉 + 写回 Layer 1 骨架）
                ↓
           🔄 Loop 判断：还有下一卷吗？
                │                    │
           ✅ 继续               ❌ 停止 → 📦 Output 最终出稿
                │
                ▼
           📝 Prompt（骨架记忆 + 下一卷大纲 → 自然语言）
                ↓
           🤖 LLM → Edit → Refine → 循环...

          ── 旁路（EventBus 事件，不参与工作流连线） ──
EventBus ← ⚙️ Kernel 发出事件
                ├── 🗄️ Storage（订阅 → 持久化到 IndexedDB）
                ├── 🕸️ Graph（订阅 → 渲染图谱）
                └── 📋 LogPanel（订阅 → 记录日志）
```

**流程说明**：

| 步骤 | 节点 | 做的事 |
|------|------|--------|
| ① | 💡 Idea | 输入想法："写一个修仙故事" |
| ② | 📋 Outline | 填写结构化大纲（世界观/人物/红线/卷大纲/锚点），写入约束闸门 |
| ③ | ⚙️ Kernel | 注入约束 + 查记忆 → 提供增强上下文 |
| ④ | 📝 Prompt | 将结构化骨架记忆翻译成自然语言提示词 |
| ⑤ | 🤖 LLM | 写完整一卷（开端→发展→高潮→低谷→结束） |
| ⑥ | ✏️ Edit | 人工校对整卷文本 |
| ⑦ | 📦 Output | 输出本卷全文（累积出稿） |
| ⑧ | 🦴 Refine | 将整卷精炼为骨架三元组（只保留转折点） |
| ⑨ | ⚙️ Kernel(feedback) | 接收骨架 → 验幻觉 → 写回洋葱层 |
| ⑩ | 🔄 Loop | 判断是否继续下一卷 |
| ⑪ | ...循环 | 回到步骤④，Kernel自动注入更新后的记忆 |

**循环单位**：一个完整故事弧（卷/幕），不是单章。

**终止条件**：
- Loop 节点设定卷数到达（如5卷写完自动停）
- 用户手动点 [⏹ 停止]

**内核记忆在循环中的变化**：

```
第1卷写完 → 精炼 → 内核记住：23条骨架
第2卷写完 → 精炼 → 内核记住：23+20=43条骨架
第3卷写完 → 精炼 → 内核记住：43+25=68条骨架
...
第10卷写完 → 精炼 → 内核记住：约200条骨架（不膨胀）
```

## 六、内核遗忘机制

### 6.1 为什么需要遗忘

几百万字的小说，内核不可能记住所有末梢细节。遗忘机制确保：
- **提示词不超长**：只保留骨架级记忆进入 LLM prompt
- **注意力聚焦**：LLM 只看到关键转折点，不会被日常细节干扰
- **成本可控**：保持 prompt Token 数稳定

### 6.2 五层洋葱与遗忘策略

| 层 | 名称 | 遗忘策略 | 保留规则 |
|----|------|---------|---------|
| 🧅 **Layer 0** | 核心事实（大纲设定） | **永不遗忘** | 用户手动确认 |
| 🧅 **Layer 1** | 故事骨架（精炼后转折点） | **永不遗忘** | 每卷精炼后写入 |
| 🧅 **Layer 2** | 近期详情（最近N章） | 窗口外降级 | 时间窗口可配置 |
| 🧅 **Layer 3** | 末梢细节（很久以前） | **优先遗忘** | 引用计数<阈值 |
| 🧅 **Layer 4** | 索引层（只存"去哪查"） | 不占活跃内存 | 需要时去Storage查 |

### 6.3 三条遗忘规则

**规则1：层阶保护**
```
Layer 0: (林夜, 灵根, 冰灵根)        → ❌ 永不删
Layer 1: (林夜, 第一卷, 筑基成功)     → ❌ 永不删
Layer 2: (林夜, 第12章, 吃了一碗面)   → ⏳ 窗口外降级
Layer 3: (林夜, 第3章, 穿蓝色衣服)    → ✅ 优先遗忘
```

**规则2：引用计数衰减**
```
每个三元组记录"被查询次数"：
  (林夜, 修为, 金丹期)    → 被查询 47 次 → 保留
  (林夜, 第3章, 吃面)     → 被查询 0 次  → 遗忘
  (林夜, 穿蓝色衣)        → 被查询 1 次  → 可能遗忘
```

**规则3：时间窗口滚动**
```
只保留最近 N 章的完整详情，窗口外的末梢自动降级：

当前写到第10章，窗口=7章：
  第1-3章 → 只保留Layer 1骨架，末梢已遗忘
  第4-10章 → Layer 2完整保留
```
