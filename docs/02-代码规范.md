## 1. 项目架构与模块划分

### 1.1 目录结构与职责

```
src/
├── components/      # 通用 UI 组件（可引用 store、theme、utils）
├── canvas/          # 画布相关组件与逻辑（引用 store、nodes）
├── nodes/           # 节点渲染组件（NodeRenderer、NodePort、NodeWrapper）
├── store/           # 状态管理（不引用 components！只引用 types、utils）
├── plugins/         # 插件目录（每个插件一个子目录，含 manifest.json）
│   ├── FIXED_IDS.md # 插件 fixedId 注册表（新增插件前必读）
│   ├── world-editor/
│   └── zhang-gu-si/
├── plugin-system/   # 插件框架（加载器、注册表、沙箱、类型定义）
├── dataflow/        # 数据流引擎（数据包、执行引擎、AI 节点执行）
├── runtime/         # Worker 运行时（NodeWorker、WorkerPool）
├── services/        # 服务层（AI 服务等外部服务调用）
├── theme/           # 主题配置
├── types/           # 全局类型定义
├── constants/       # 全局常量
├── utils/           # 通用工具函数
├── hooks/           # 自定义 React Hooks
├── floating/        # 浮动面板组件
├── sidebar/         # 侧边栏组件
└── config/          # 配置文件（JSON schema 等）
```

### 1.2 依赖方向规则（禁止反向依赖）

```
components → store → types/utils
                ↓
            plugin-system → plugins
                ↓
           dataflow → runtime
```

- **`store/`** 不可引用 `components/` 中的内容
- **`utils/`** 不可引用任何 React 相关内容
- **`plugins/`** 内部可引用 `plugin-system/`，但不可反过来
- **`theme/`** 可被任何组件引用

## 3. 代码命名规范（TypeScript）

### 3.1 通用规则

| 类型 | 规则 | 示例 |
|------|------|------|
| **变量** | `camelCase` | `pluginLoaded`, `runState`, `btnBase` |
| **函数** | `camelCase` | `generateNodeId()`, `handleRun()` |
| **布尔值** | `is`/`has`/`should`/`can` 前缀 | `isRunning`, `canUndo`, `hasCycle()` |
| **常量（模块级）** | `camelCase` | `btnBase`, `consoleCaptureRef` |
| **常量（魔术数字/字符串）** | `UPPER_SNAKE_CASE` | `STYLE_PRESETS`, `WORLD_RULE_PRESETS` |
| **私有/内部函数** | 无特殊前缀，按 `camelCase` | `generateNodeId()`（模块内不导出即可） |
| **参数** | `camelCase` | `nodeId: string`, `position: XYPosition` |

### 3.2 接口与类型

| 类型 | 规则 | 正确示例 | 错误示例 |
|------|------|----------|----------|
| **接口** | `PascalCase`，**不加 I 前缀** | `PluginManifest`, `CanvasState` | `IPluginManifest` ❌ |
| **类型别名** | `PascalCase` | `NodeExecStatus`, `VaultTab` | |
| **枚举成员** | `PascalCase` | `'idle' \| 'running'` | `'IDLE'` ❌ |
| **Props 接口** | `ComponentName + Props` | `TopToolbarProps` | |

### 3.3 Store 命名

```typescript
// ✅ 正确
export const useCanvasStore = create<CanvasState>()(...);

// 接口统一叫 XxxState（而不是 XxxStore）
export interface CanvasState {
  nodes: Node[];
  ...
}
```

### 3.4 React 组件 Props

```typescript
// ✅ Props 接口名 = 组件名 + Props
interface TopToolbarProps {
  onRun?: () => void;
  runState?: 'idle' | 'running';
}

// ✅ 回调 Props 用 on 前缀
onRun, onNodesChange, onConnect, onClose

// ✅ 事件处理函数用 handle 前缀
handleRun, handleNew, handleStyleSelect, handleWorldRuleConfirm
```

### 3.5 类型安全 —— 禁止 any

```typescript
// ❌ 禁止
const setVal = (key: string, val: any) => updateNodeData(nodeId, key, val);

// ✅ 正确做法：使用泛型或明确类型
const setVal = (key: string, val: unknown) => updateNodeData(nodeId, key, val);
// 或定义具体的联合类型
type SettingField = 'creativeIdea' | 'perspective' | 'style';
const setVal = (key: SettingField, val: string) => updateNodeData(nodeId, key, val);
```

## 4. 组件设计规范

### 4.1 组件定义方式

**统一使用 `export default function Xxx()` 方式：**

```tsx
// ✅ 统一标准
interface Props {
  nodeId: string;
}

export default function PageSetting({ nodeId }: Props) {
  // ...
}
```

### 4.2 组件文件结构

```
1. 文件头 JSDoc 注释
2. import 语句（先外部库，后内部模块）
3. Props 接口定义
4. 组件函数（export default）
5. 辅助子组件（不用 export，无 default）
```

### 4.3 组件职责

- 每个组件只做一件事
- 页面组件（`pages/`）：负责数据获取和布局
- 通用组件（`components/`）：负责 UI 呈现，通过 Props 接收数据
- 一个文件一个主要导出组件

### 4.4 Hook 使用规范

```typescript
// ✅ useEffect 的依赖数组必须显式列出所有依赖
useEffect(() => {
  useSettingsStore.getState().loadSettings();
}, []); // 只有初始化才用空数组

// ✅ useCallback 用于传递给子组件的回调
const onRunClick = useCallback(() => {
  handleRun();
}, [handleRun]);

// ✅ 状态提升：多个组件共享的状态放到 store
// ❌ 禁止：用 props drilling 传递超过 3 层
```

## 5. 状态管理规范（Zustand）

### 5.1 Store 创建模板

```typescript
/**
 * xxx-store.ts
 *
 * 职责描述
 */

import { create } from 'zustand';
import { persist } from 'zustand/middleware';

export interface XxxState {
  /** 状态字段，必须标注 JSDoc */
  data: Record<string, string>;

  // 操作方法
  setData: (key: string, value: string) => void;
  resetAll: () => void;
}

export const useXxxStore = create<XxxState>()(
  persist(
    (set, get) => ({
      data: {},

      setData: (key: string, value: string) => {
        set((state) => ({
          data: { ...state.data, [key]: value },
        }));
      },

      resetAll: () => {
        set({ data: {} });
      },
    }),
    {
      name: 'neihei-xxx',       // localStorage 键名，统一 neihei- 前缀
      partialize: (state) => ({  // 只持久化必要字段
        data: state.data,
      }),
    }
  )
);
```

### 5.2 Store 命名规范

- 接口名：`XxxState` ✅（不用 `XxxStore`）
- Store 变量名：`useXxxStore` ✅
- 文件名：`xxx-store.ts` ✅
- 统一在 `store/index.ts` 中导出

### 5.3 Store 行为规范

```typescript
// ✅ Component 中读取 Zustand store
const nodes = useCanvasStore((s) => s.nodes);

// ✅ 跨 Store 引用（在 action 方法中使用 getState）
useUndoStore.getState().snapshot();

// ❌ 禁止在 action 外通过 getState() 修改 store（应通过 action）
```

### 5.4 冗余方法禁止

```typescript
// ❌ 禁止：Zustand 本身就支持直接读取，不需要包装
getNodeState: (nodeId: string) => {
  return get().states[nodeId];
}

// ✅ 外部直接读
const state = useExecutionStore((s) => s.states['n_xxx']);
```

## 16. 快照数据规范（Snapshot Store）

### 16.1 快照定义

快照（Snapshot）用于保存和恢复画布的完整状态，包括节点、边、面板数据和流程状态。快照数据存储在 `bookshelf-store.ts` 中，持久化到 localStorage。

**快照数据结构：**

```typescript
interface BookSnapshot {
  id: string;                    // 唯一标识
  name: string;                  // 书名
  timestamp: number;             // 保存时间戳
  canvas: {
    nodes: Node[];               // 所有节点（不限插件类型）
    edges: Edge[];               // 所有连线
    collapsedNodes: string[];    // 已收起的节点
  };
  panelData: Record<string, Record<string, unknown>>;  // 所有节点的面板表单数据
  flowState: {
    mode: EditorMode;
    currentStep: number;
    stepStatus: Record<TabId, SignalStatus>;
  };
}
```

### 16.2 快照保存规则

- 保存时从各 store 同步读取最新状态（使用 `getState()`）
- 必须保存以下数据源：
  - `canvas-store`: nodes, edges, collapsedNodes
  - `panel-data-store`: 所有节点的面板数据
  - `world-editor-flow-store`: mode, currentStep, stepStatus
- 保存时弹出命名对话框，由用户输入书名
- 默认书名为 `作品_MM/DD HH:mm` 格式

### 16.3 快照恢复规则

- 恢复时调用 `canvas-store.loadCanvas()` 恢复节点和边
- 逐条恢复 `panel-data-store` 中每个节点的数据
- 恢复 `world-editor-flow-store` 的 mode、currentStep 和 stepStatus
- 恢复后自动关闭书架面板

### 16.4 书架 UI 规范

- 模态框尺寸：900x440px（标题栏 40px + 书架区域 300px + 详情栏 100px）
- 每排显示 7 本书，书本尺寸 70x110px
- 书本以竖条矩形展示，显示书名前两个字符
- 选中书本高亮边框 `#6a9fb5`
- 详情栏显示：书名、保存时间、节点数、连线数、流程进度

### 16.5 快照更新规则（继存）

- `updateBook(id)` 方法用于用当前画布最新状态覆盖指定书的快照数据
- 更新逻辑与 `saveBook` 相同，但不创建新条目，而是更新已有条目的所有字段
- 更新后 `timestamp` 刷新为当前时间
- 如果 `selectedBookId` 为 null，调用方应提示用户「请先在书架中选中一本书」
- 更新成功后弹出居中提示窗口，显示「已缓存：{书名}」，用户点击确定关闭
- 如果未选中书或书已被删除，同样弹出提示窗口告知用户

### 16.6 文件命名

|------|------|
| `src/store/bookshelf-store.ts` | 快照状态管理 |
| `src/components/BookshelfPanel.tsx` | 书架面板组件 |

## 17. 弹出菜单与模态框规范

### 17.1 弹出菜单（Dropdown Menu）

弹出菜单用于工具栏按钮的次级操作选择，如「书架」按钮点击后弹出「打开书架」「保存此书」选项。

**设计规范：**
- 弹出菜单位于触发按钮的正下方，左对齐
- 背景色使用 `#0d0d0d`（面板色），边框 `#1e1e1e`
- 圆角 8px，阴影 `rgba(0,0,0,0.4)`
- 每个菜单项高度 36px，内边距 `8px 16px`
- 菜单项悬停时背景变为 `#1a1a1a`
- 点击菜单项后菜单自动关闭
- 点击菜单外部区域或按 ESC 键关闭菜单

**组件结构：**

```tsx
// 弹出菜单状态由父组件管理
const [menuOpen, setMenuOpen] = useState(false);

// 菜单项定义
const menuItems = [
  { label: '打开书架', onClick: handleOpenBookshelf },
  { label: '保存此书', onClick: handleSaveBook },
];

// 渲染菜单
{menuOpen && (
  <div style={overlayStyle} onClick={() => setMenuOpen(false)}>
    <div style={menuStyle}>
      {menuItems.map((item) => (
        <div key={item.label} style={menuItemStyle} onClick={item.onClick}>
          {item.label}
        </div>
      ))}
    </div>
  </div>
)}
```

### 17.2 模态框（Modal Dialog）

模态框用于展示需要用户交互的较大界面，如「书架」面板。

**设计规范：**
- 全屏半透明遮罩层，背景 `rgba(0,0,0,0.6)`
- 模态框居中显示，固定尺寸（如 900x400）
- 背景色 `#0d0d0d`，边框 `#1e1e1e`，圆角 12px
- 标题栏高度 40px，右侧有关闭按钮
- 内容区域分上下两层（或按需布局），通过 flex 排列
- 点击遮罩层或关闭按钮关闭模态框

**组件结构：**

```tsx
export default function XxxPanel({ isOpen, onClose }: Props) {
  if (!isOpen) return null;

  return (
    <div style={overlayStyle} onClick={onClose}>
      <div style={panelStyle} onClick={(e) => e.stopPropagation()}>
        {/* 标题栏 */}
        <div style={headerStyle}>
          <span style={titleStyle}>标题</span>
          <button onClick={onClose} style={closeBtnStyle}>✕</button>
        </div>
        {/* 内容区域 */}
        <div style={contentStyle}>
          {/* 上层 */}
          <div style={topSectionStyle}>...</div>
          {/* 分割线 */}
          <div style={dividerStyle} />
          {/* 下层 */}
          <div style={bottomSectionStyle}>...</div>
        </div>
      </div>
    </div>
  );
}
```

### 17.3 命名规范

| 类型 | 文件命名 | 组件名 | 说明 |
|------|----------|--------|------|
| 弹出菜单 | 内联在父组件中 | 无独立文件 | 简单菜单不拆分为独立文件 |
| 模态框 | `XxxPanel.tsx` | `XxxPanel` | 复杂面板拆分为独立组件文件 |
