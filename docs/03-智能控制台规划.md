## 一、概述

### 1.1 什么是智能控制台？

智能控制台是一个**浮动面板插件**，位于画布右侧（宽 300px，高度等同画布），通过**空格键**快速唤起/关闭。它提供两大核心功能：

| Tab | 功能 | 一句话描述 |
|-----|------|-----------|
| 🔍 **调试 (Debug)** | 节点测试与诊断 | 选中画布节点，查看输入/输出数据，手动输入测试命令执行 |
| 📥 **智能导入 (Smart Import)** | 文档→结构化数据 | 上传大纲文档 + 规范 JSON，AI 自动分析并补全到目标节点 |

### 1.2 设计原则

1. **不侵入内核**：所有功能在外观层实现，不修改内核代码
2. **复用现有基础设施**：尽可能复用已有的 store、service、dataflow
3. **即插即用**：作为独立插件，不影响现有工作流
4. **用户可控**：所有 AI 操作需用户确认后再执行

## 二、功能详述

### 2.1 Tab1: 调试 (Debug)

#### 2.1.1 节点数据查看器

当用户在画布上**选中一个节点**时，调试面板自动显示该节点的完整数据：

```
┌──────────────────────────────────────┐
│ 🔍 调试                              │
│                                      │
│ 选中节点: n_xxx (Kernel)             │
│ ┌─ 输入数据 ──────────────────────┐  │
│ │ text: "用户输入的创意内容..."     │  │
│ │ triples: [...]                   │  │
│ │ feedback: ""                     │  │
│ └──────────────────────────────────┘  │
│ ┌─ 输出数据 ──────────────────────┐  │
│ │ aiOutput: "AI 返回的结果..."     │  │
│ │ validated: {...}                 │  │
│ │ _aiLoading: false                │  │
│ │ _aiError: null                   │  │
│ └──────────────────────────────────┘  │
│ ┌─ 端口状态 ──────────────────────┐  │
│ │ 输入端口: trigger-in (signal) ✓  │  │
│ │           text (string)     ✓     │  │
│ │ 输出端口: trigger-out (signal)   │  │
│ │           response (string)       │  │
│ └──────────────────────────────────┘  │
└──────────────────────────────────────┘
```

**数据来源：**
- 节点 `data` 字段 → `canvas-store.nodes[n].data`
- 面板数据 → `panel-data-store.data[nodeId]`
- 端口定义 → 从 `pluginRegistry` 读取该节点类型的 manifest

#### 2.1.2 手动测试执行

用户可以在输入框中输入测试文本，模拟数据流触发该节点执行：

```
┌─ 测试执行 ──────────────────────────┐
│ 测试输入:                           │
│ [________________________________]  │
│ [📎 附件]                           │
│                                     │
│ 选择 API: [下拉: GPT-4o ▼]          │
│                                     │
│ [▶ 执行测试]                        │
│                                     │
│ ┌─ 执行结果 ──────────────────────┐ │
│ │ ✅ 成功 (1.2s)                   │ │
│ │ "AI 返回的测试结果..."            │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

**执行流程：**
1. 用户输入测试文本（或上传文件作为输入）
2. 选择使用的 AI 模型（从 `api-settings-store` 读取）
3. 点击「执行测试」
4. 调用 `executeAiNode()` 复用现有执行逻辑
5. 显示执行结果、耗时、状态

#### 2.1.3 执行历史

记录对该节点的多次测试结果，方便对比：

```
┌─ 执行历史 ──────────────────────────┐
│ [#3] 10:32:15 ✅ 1.2s "测试文本3"   │
│ [#2] 10:31:20 ❌ 0.5s "连接超时"    │
│ [#1] 10:30:00 ✅ 2.1s "测试文本1"   │
```

#### 2.2.1 核心场景

> **用户上传小说大纲/世界观文档 + 世界编辑器输出规范 JSON → AI 分析并补全缺失数据 → 写入目标节点**

```
│ (支持 .txt .md .docx .json)          │
│                                      │
│ 步骤 2: 上传规范 JSON                │
│ [📎 选择文件] world_editor_schema.json│
│                                      │
│ 步骤 3: 选择目标节点                 │
│ [下拉选择目标节点 ▼]                  │
│  n_001 (WorldEditor)                 │
│  n_002 (WorldEditor)                 │
│                                      │
│ 步骤 4: 选择 AI 模型                 │
│ [下拉选择 API ▼]                     │
│  GPT-4o / Claude / 本地模型          │
│                                      │
│ [🚀 AI 智能分析并补全]               │
│                                      │
│ ┌─ 补全结果预览 ──────────────────┐ │
│ │ ✅ 作品设定: 已补全 5/7 字段     │ │
│ │ ✅ 世界构建: 已补全 6/7 字段     │ │
```

#### 2.2.2 工作流程详解

```
┌─────────────┐    ┌──────────────────┐    ┌──────────────┐
│ 用户上传     │    │ AI 分析补全      │    │ 写入目标节点  │
│             │    │                  │    │              │
│ ① 大纲文档  │───→│ ③ 读取文档内容   │    │ ⑥ 写入        │
│ ② schema   │    │ ④ 对照 schema    │───→│ panel-data    │
│   JSON      │    │ ⑤ 生成补全数据   │    │ -store       │
└─────────────┘    └──────────────────┘    └──────┬───────┘
                                                   │
                                                   ↓
                                            ┌──────────────┐
                                            │ 触发数据流    │
                                            │ propagateFrom │
                                            │ -Node()       │
                                            └──────────────┘
```

#### 2.2.3 AI Prompt 设计

```typescript
/**
 * 构建智能导入的 Prompt
 * 
 * 告诉 AI：
 * 1. 用户上传的文档内容（大纲/世界观）
 * 2. 目标 JSON schema 结构
 * 3. 要求：分析文档，按 schema 补全所有字段
 * 4. 输出格式：严格按 schema 结构的 JSON
 */
function buildCompletionPrompt(
  documentContent: string,
  schemaJson: object
): string {
  return `你是一个小说创作助手。用户上传了以下文档内容：

=== 文档内容 ===
${documentContent}

=== 目标数据结构 ===
${JSON.stringify(schemaJson, null, 2)}

请分析文档内容，按照上述数据结构补全所有字段。
要求：
1. 严格遵循 JSON schema 的结构输出
2. 文档中已有的信息直接填入
3. 文档中缺失的信息，根据上下文合理推断补全
4. 输出必须是合法的 JSON 对象
5. 不要添加 schema 中不存在的字段

请直接输出 JSON，不要包含其他说明文字。`;
}
```

## 六、注意事项

### 6.1 边界情况

1. **未选中节点时**：调试 Tab 显示「请在画布上选中一个节点」
2. **节点无输入端口**：显示「该节点没有输入端口」
3. **AI 调用失败**：显示错误信息，保留用户输入不丢失
4. **文件过大**：限制上传文件大小（建议 10MB），超出时提示
5. **schema 不匹配**：校验上传的 JSON 是否为合法的 schema 格式

### 6.2 安全考虑

1. 上传的文件内容仅在内存中处理，不写入磁盘
2. AI 分析结果需用户确认后才写入目标节点
3. 遵循项目现有安全规范（插件沙箱、数据校验）

### 6.3 性能考虑

1. 面板打开时才加载内容（懒加载）
2. 节点数据使用 Zustand 选择器最小化订阅
3. 执行历史限制最多 100 条，超出自动清理旧记录

### 7.3 用户场景示例

**场景 1：调试工作流**
1. 用户在画布上搭建了 `Idea → Kernel → LLM → Output` 工作流
2. 发现 Output 结果不对，按**空格键**打开智能控制台
3. 选中 Kernel 节点，查看输入/输出数据
4. 在测试输入框中输入测试文本，选择 GPT-4o，点击执行
5. 查看执行结果，定位问题

**场景 2：导入已有世界观**
1. 用户有一份写好的 2 万字小说世界观文档
2. 在画布上添加一个 WorldEditor 节点
3. 按**空格键**打开智能控制台，切换到「智能导入」Tab
4. 上传世界观文档 + 下载的 world_editor_schema.json
5. 选择目标 WorldEditor 节点，选择 AI 模型
6. 点击「AI 智能分析并补全」
7. 预览补全结果，确认后写入节点
8. 继续自动化生成小说
