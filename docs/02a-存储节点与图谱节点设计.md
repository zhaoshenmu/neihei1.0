# 🗄️ 存储节点与 🕸️ 图谱节点设计补充

## 为什么需要这份文档？

`docs/02-内核架构.md` 定义了内核的「三原则」（查记忆、验幻觉、写回），但原设计中有两个越界的标签（图谱扩展、执行控制）已被移出内核。这份文档说明两个替代方案：

1. **🕸️ Graph 图谱节点** — 替代原标签4「图谱扩展」，作为画布独立节点只读可视化内核数据
2. **🗄️ Storage 存储节点** — 负责持久化，完全独立于内核

---

## 一、核心架构变更前后对比

### 修改前（内核越界）

```
⚙️ Kernel 控制面板
├── 📋 记忆层     ✅ 属于三原则
├── 📋 约束       ✅ 属于三原则
├── 📋 检测       ✅ 属于三原则
├── 📋 图谱扩展   ❌ 推理功能，越界
├── 📋 执行控制   ❌ LLM调度，越界
└── 📋 设置       ✅ 属于三原则
```

### 修改后（内核纯净）

```
⚙️ Kernel 控制面板
├── 📋 记忆层     ✅ 属于三原则
├── 📋 约束       ✅ 属于三原则
├── 📋 检测       ✅ 属于三原则
└── 📋 设置       ✅ 属于三原则

独立节点（画布上工作流中的节点）：
├── 🕸️ Graph     ✅ 只读可视化内核数据
└── 🗄️ Storage   ✅ 独立持久化
```

## 二、EventBus — 连接所有组件的隐形中线

内核不直接与任何节点组件对话。所有跨组件通信走 EventBus：

```
⚙️ Kernel 写回完成
    ↓
EventBus.emit('kernel:memory-updated', { layers, version, delta })
    ├── 🕸️ Graph 节点收到 → 更新图谱
    ├── 🗄️ Storage 节点收到 → 写入 IndexedDB
    └── 📋 LogPanel 收到 → 记录日志
```

### 事件类型全集

| 事件名 | 发布者 | 订阅者 | 数据内容 |
|--------|-------|-------|---------|
| `kernel:memory-updated` | ⚙️ Kernel | 🕸️ Graph, 🗄️ Storage, 📋 LogPanel | 完整四层快照 + 增量 |
| `kernel:validation-result` | ⚙️ Kernel | 📋 LogPanel | 幻觉检测通过/冲突 |
| `user:request-edit` | 🕸️ Graph, ✏️ Edit | ⚙️ Kernel | 用户请求修改三元组 |
| `kernel:edit-processed` | ⚙️ Kernel | 🕸️ Graph, ✏️ Edit | 修改结果 |
| `storage:data-restored` | 🗄️ Storage | ⚙️ Kernel | 从持久层恢复完成 |

## 三、🕸️ Graph 节点详细设计

### 3.1 一句话概括

> Graph 节点是一块连接在内核上的"显示屏"。它不存数据，只管可视化。

### 3.2 数据通路

```
⚙️ Kernel 写回
    ↓
EventBus: 事件附带只读快照（layer0 + layer1 + layer2 的 Triple[]）
    ↓
🕸️ Graph 节点
    ├─ 版本号比对（防乱序）
    ├─ 增量更新（只重绘变化部分）
    └─ 保留用户拖拽的位置
```

### 3.3 版本号对齐机制

```
event.version > localVersion  → 全量更新（新版本）
event.version == localVersion  → 增量更新（同一版本的新增量）
event.version < localVersion   → 丢弃（旧版本乱序到达）
```

### 3.4 用户操作规则

| 用户操作 | 允许？ | 说明 |
|---------|-------|------|
| 拖拽节点位置 | ✅ | 纯视觉，不涉及数据 |
| 缩放/平移 | ✅ | 纯视觉 |
| 点击查看详情 | ✅ | 只读读取本地快照 |
| **删除连线/节点** | ❌ 需通过内核 | Graph 发事件 → 内核处理 → 更新后同步回来 |
| **新增节点/连线** | ❌ 需通过内核 | 同上 |

### 3.5 视觉编码

| 图层 | 节点样式 | 边框 | 含义 |
|------|---------|------|------|
| Layer 0 | 实心圆 | 金色 🔒 | 用户已确认，不可修改 |
| Layer 1 | 实心圆 | 银色 ✓ | 多源验证的推断事实 |
| Layer 2 | 虚线圆 | 灰色 ? | AI生成，待用户确认 |
| Layer 3 | 不显示 | - | 临时数据，不渲染 |

## 四、🗄️ Storage 节点详细设计

### 4.1 一句话概括

> Storage 节点是内核记忆的"存档柜"。它不连线，只监听事件，负责把内存中的数据存到硬盘，下次打开页面时再读回来。

### 4.2 定位

Storage 节点不属于工作流的主链路节点。它通过 EventBus 监听内核事件，将 Kernel 的 Layer 0-2 三元组数据持久化到 IndexedDB，并在页面加载时自动恢复。

**与 Graph 的关系**：Storage 和 Graph 之间**不需要连线**，它们各自独立订阅 Kernel 的事件。

### 4.3 持久化流程

```
📱 用户使用中
    ↓
⚙️ Kernel 写回 → 发出事件
    ↓
🗄️ Storage 收到
    ├─ 提取 layers.layer0 + layer1 + layer2
    ├─ 版本号比对
    └─ 写入 IndexedDB

📱 用户关闭页面 → 下次打开
    ├─ Storage 启动
    ├─ 从 IndexedDB 读取最后快照
    ├─ 调用 kernel.restoreFromStorage(layers)
    ├─ 内核恢复 Layer 0-1
    └─ 内核发出事件 → Graph 自动恢复显示
```

### 4.4 未来扩展 — 多小说书架

Storage 节点未来可扩展为「我的书架」，支持多本小说的存档管理和切换：

```
🗄️ 我的书架（双击打开）
├── 📚 仙道无双     → 第3卷/第15章 → [继续写作]
├── 📚 都市潜龙     → 第1卷/第8章  → [继续写作]
├── 📚 星际争霸     → 大纲阶段     → [新建]
└── [➕ 新建小说]
```

切换小说的完整链路：
```
选《都市潜龙》
    ↓
Storage 读出 v18 快照
    ↓
写回 Kernel（恢复 Layer 0-1）
    ↓
Kernel 发出事件
    ├── Graph 收到 → 恢复图谱显示
    └── 🔄 Loop 收到 → 恢复写作进度（第1卷/第8章）
    ↓
接着写，就像没关过页面
```

### 4.5 存储位置

| 存储目标 | 适用场景 | 容量限制 |
|---------|---------|---------|
| IndexedDB | 默认推荐 | 浏览器可用空间的 50%（通常几百 MB） |
| localStorage | 小型项目 | 5-10 MB |
| 未来可扩展 | 云端同步 | 待定 |

### 4.6 多 Storage 节点（可选高级用法）

用户可以在画布上拖入多个 Storage 节点，分别存储不同类型的数据：

| 节点标签 | 存储内容 | 过滤规则 |
|---------|---------|---------|
| 🗄️ 角色档案库 | `(林夜, 拥有, 青冥剑)` 等 | subject 是角色名 |
| 🗄️ 世界观库 | `(青城山, 位于, 蜀地)` 等 | subject 是地理/设定 |
| 🗄️ 情节库 | `(第5章, 事件, 林夜获剑)` 等 | subject 是章节 |

## 六、边界红线（绝对不允许的越界行为）

| 越界行为 | 为什么不能做 | 正确做法 |
|---------|------------|---------|
| 🕸️ Graph 节点直接修改内核数据 | 破坏三原则的数据一致性 | 发事件 -> 内核处理 -> 同步回来 |
| 🗄️ Storage 节点修改三元组内容 | 持久化不应该改动数据 | 原样写入，原样读回 |
| ⚙️ Kernel 直接调用 LLM | 内核变成调度器 | 通过 🤖 LLM 节点调用 |
| ⚙️ Kernel 直接渲染图谱 | 内核变成渲染器 | 🕸️ Graph 节点订阅事件 |
| ⚙️ Kernel 控制执行进度 | 内核变成编排器 | 由用户在工作流中控制 |
