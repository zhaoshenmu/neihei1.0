# 🧅 架构总览

## 🔴 核心铁律

> **内核只做三件事：查记忆、验幻觉、写回**
>
> 任何想往内核里塞「第四件事」的行为，都必须先审视这个文档。
> 如果你发现自己正在往内核里加「提示词管理」「模型调用」「格式渲染」「数据导出」
> 或其他不属于三原则的功能————停下来，把它放到外面。
>
> 详细三原则说明见 `02-内核架构.md#一三原则核心铁律`

## 一、三层洋葱架构

```
    ┌─────────────────────────────────┐
    │  外观层 (Vehicle)                │
    │  小说 / 短剧剧本 / 可视化图表    │
    │  ─── 格式渲染、风格控制          │
    │  ─── 由 chajian/ 输出插件负责    │
    ├─────────────────────────────────┤
    │  内核层 (Engine)                 │
    │  洋葱三元组引擎                  │
    │  ─── 记忆/推理/一致性            │
    │  ─── 对抗失忆和幻觉              │
    ├─────────────────────────────────┤
    │  API层 (Fuel)                    │
    │  LLM适配器 / 本地模型 / 云端API   │
    │  LM Studio / OpenAI / Claude     │
    └─────────────────────────────────┘
```

### 比喻对照

| 比喻 | 技术实现 |
|------|---------|
| 🚗 汽车(小说) | NovelGenerator 插件 |
| 🏍️ 摩托车(短剧) | ScriptGenerator 插件 |
| 🛢️ 汽油(API) | LLMAdapter 接口 |
| 🏭 发动机(内核) | Kernel Engine |
| 🎛️ 方向盘(控制) | Kernel 面板标签 |
| 📋 仪表盘(监控) | LogPanel + 置信度可视化 |

## 二、画布两层结构

画布上共存两个层次，由不同类型的节点区分：

```
┌────────────────────────────────────────────────────────────────┐
│                     画布 (React Flow)                           │
│                                                                │
│  ┌──────────────── 工作流层（你搭的管道）─────────────────────┐ │
│  │                                                           │ │
│  │   💡 Idea ──► ⚙️ Kernel ──► 🤖 LLM ──► 📦 Output         │ │
│  │                                                           │ │
│  └───────────────────────────────────────────────────────────┘ │
│                          │                                     │
│                          ▼  内核同步数据到画布                   │
│                          │                                     │
│  ┌──────────────── 图谱层（自动渲染）────────────────────────┐ │
│  │   ┌──────┐         ┌──────┐                               │ │
│  │   │ 林夜  │──拥有──►│青冥剑│                               │ │
│  │   └──┬───┘         └──────┘                               │ │
│  │       │位于                                               │ │
│  │       ▼                                                   │ │
│  │   ┌──────┐         ┌──────┐                               │ │
│  │   │青城山│──包含──►│传承大殿│                              │ │
│  │   └──────┘         └──────┘                               │ │
│  └───────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘
```

### 工作流层节点类型

| 节点 | 图标 | 用途 | 输入端口 | 输出端口 |
|------|------|------|---------|---------|
| **Idea** | 💡 | 用户想法输入 | - | `text`, `triples` |
| **Kernel** | ⚙️ | 记忆+防幻觉引擎（唯一核心） | `text`, `triples`, `feedback` | `text`, `triples`, `validated` |
| **LLM** | 🤖 | 调用AI生成 | `prompt`, `context` | `response`, `raw_triples` |
| **Edit** | ✏️ | 人工干预节点 | `text`, `cmd` | `text` |
| **Output** | 📦 | 插件化输出容器 | `text`, `triples` | - |
| **Plugin** | 🧩 | 通用扩展（复用 chajian/） | 由 manifest 定义 | 由 manifest 定义 |

### 图谱层节点

图谱层的节点 = 内核 TripleStore 中的实体自动渲染。每个实体是一个节点，每条三元关系是一条边。节点颜色区分洋葱层：

| 洋葱层 | 节点边框颜色 | 含义 |
|--------|------------|------|
| Layer 0 | 🥇 金色 | 核心事实（不可变更） |
| Layer 1 | 🥈 银色 | 高置信度推断 |
| Layer 2 | ⚪ 灰色 | 待验证假设 |
| Layer 3 | 🔵 蓝色（虚线） | 临时探索关系 |

## 三、核心原则

1. **所有数据流经内核**：无论什么工作流模式，Idea→LLM→Output 之间必须经过 Kernel
2. **内核只做三件事**：查记忆增强输入 → 验证输出防幻觉 → 写回记忆
3. **输出完全插件化**：Output 节点本身不渲染任何格式，由 chajian/ 插件决定
4. **画布即图谱**：图谱不需要额外工具，内核数据直接在画布上渲染为节点+连线

## 四、三种工作模式

### 模式A：全自动
```
💡 Idea ──► ⚙️ Kernel ──► 🤖 LLM ──► ⚙️ Kernel ──► 📦 Output
```
你只负责在 Idea 输入，等 Output 看结果。

### 模式B：半自动
```
💡 Idea ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ⚙️ Kernel ──► ✏️ Edit ──► 📦 Output
```
你在关键环节介入修改提示词或审查结果。

### 模式C：全手动
```
💡 Idea ──► ✏️ Edit ──► ⚙️ Kernel ──► ✏️ Edit ──► 🤖 LLM ──► ✏️ Edit ──► ⚙️ Kernel ──► 📦 Output
```
每步都手动操作，Kernel 只负责记忆和验证。
