# 智能控制台规范 (Smart Console)

> **文档状态：** 已实现 v2.0
> **关联插件：** `src/plugins/smart-console/`
> **fixedId：** `004`
> **实现版本：** 聊天 + 调试模式（无 Tab，模式切换）

---

## 1. 概述

### 1.1 是什么？

智能控制台是一个**浮动面板插件**，位于画布右侧，通过右下角按钮打开/关闭。它提供两种交互模式：

| 模式 | 用途 | 一句话描述 |
|------|------|-----------|
| 💬 **聊天模式（默认）** | 纯聊天 | 不显示任何节点/AI 信息，纯粹的对话界面 |
| 🔧 **调试模式** | 节点测试与诊断 | 左侧弹出 300px 调试面板，查看节点数据、调试指令 |

### 1.2 设计原则

1. **模式互斥**：聊天和调试是同一面板的两种模式，不是两个 Tab，通过底部按钮切换
2. **聊天纯粹**：聊天模式不显示任何节点信息，是干净的消息界面
3. **调试自洽**：调试模式下所有执行结果只出现在调试面板的"执行结果"区
4. **自包含**：面板自己管理开关状态和 UI，不依赖外部组件
5. **内联样式**：遵循项目主题系统，所有样式使用内联 `style={}`

## 4. 状态管理规范

### 4.1 Store 定义

Store 定义在 `Panel.tsx` 内部（使用 `create()` 内联创建），不单独文件：

```typescript
interface SmartConsoleState {
  /** 面板开关 */
  isOpen: boolean;
  togglePanel: () => void;
  openPanel: () => void;
  closePanel: () => void;

  /** 模式切换 */
  isDebugMode: boolean;
  toggleDebugMode: () => void;

  /** 聊天消息 */
  messages: ChatMessage[];
  addMessage: (msg: Omit<ChatMessage, 'id' | 'timestamp'>) => void;
  updateMessage: (id: string, content: string) => void;
  deleteMessage: (id: string) => void;
  clearMessages: () => void;

  /** AI 回复加载状态 */
  isAiResponding: boolean;
  setIsAiResponding: (v: boolean) => void;

  /** 调试输出 */
  debugOutput: string;
  setDebugOutput: (output: string) => void;
  appendDebugOutput: (output: string) => void;
  clearDebugOutput: () => void;
}
```

### 4.2 聊天消息结构

```typescript
interface ChatMessage {
  id: string;           // `msg_{timestamp}_{random}`
  role: 'user' | 'assistant' | 'system';
  content: string;
  timestamp: number;
}
```

### 4.3 Store 方法说明

| 方法 | 说明 |
|------|------|
| `updateMessage(id, content)` | 按 id 更新某条消息的 content（用于流式逐字更新 AI 回复） |
| `deleteMessage(id)` | 按 id 删除某条消息（右键菜单使用） |
| `clearMessages()` | 清空所有消息（切换 API 时自动调用） |
| `setIsAiResponding(v)` | 设置 AI 是否正在回复中（控制加载动画显示） |

### 4.3 Store 命名规范

- hook 名：`useSmartConsoleStore`
- 状态接口：`SmartConsoleState`
- 不持久化到 localStorage（面板状态、消息、调试输出均为会话级）

## 6. 调试模式规范

### 6.1 调试面板内容结构

从上到下依次：

1. **节点信息**（未选中节点时显示"未选中节点"提示）
   - ID
   - 类型
   - fixedId
   - 位置坐标

2. **节点间数据流**
   - 当前节点显示区：
     - `📥 text（从上游接收的数据）`
     - `📤 aiOutput（AI 处理结果）`
   - 上游节点列表：显示每个上游节点的 text 值
   - 下游节点列表：显示每个下游节点的 aiOutput 值
   - 无连接时显示"该节点无上下游连接"

3. **面板数据**（折叠 `details` 组件）
   - 显示 `panel-data-store.data[nodeId]` 所有字段
   - 无数据时显示"无面板数据"

4. **执行结果**
   - 实时更新，最大高度 300px，可滚动
   - 为空时显示"输入调试指令，结果会显示在这里"

### 6.2 调试指令

| 指令关键词 | 行为 |
|-----------|------|
| `运行` / `执行` / `调用ai` | 触发选中节点的 AI 执行 |
| `展示输出` / `显示输出` / `ai输出` | 显示节点的 aiOutput |
| `展示输入` / `显示输入` / `输入内容` | 显示节点的 text 输入 |
| 其他文本 | 写入选中节点的 text 字段 |

### 6.3 world-editor 节点执行

当调试指令为"运行"且选中节点类型为 `world-editor` 或包含 `Outline` 时：

1. 调用 `world-editor-flow-store` 的完整执行流程（5 个步骤）
2. 等待节点执行完成（超时 120s）
3. 执行后写入节点 data：
   - `text`：简短摘要（字段名称列表）
   - `aiOutput`：完整面板数据 JSON
4. 显示执行结果、新增字段数

### 6.4 普通节点执行

当调试指令为"运行"且选中节点有连边时：

1. 检查下游节点类型是否在 `pluginRegistry` 中有注册（有 AI 逻辑）
2. 调用 `executeAiNode()` 执行
3. 无连边时显示当前节点的 text/aiOutput/panel-data 信息

## 7. 聊天模式规范

### 7.1 空状态

- 显示 💬 图标
- 标题："智能控制台"
- 提示文字：
  ```
  输入消息开始聊天
  🔧 点击右上角按钮切换到调试模式
  ```

### 7.2 消息气泡

| 角色 | 样式 |
|------|------|
| user | 右对齐，蓝色调背景 |
| assistant | 左对齐，灰色背景 |
| system | 居中，透明背景 |

角色名 + 时间显示在气泡内容**上方**（HH:mm:ss）

批量删除模式下，角色名左侧会显示一个选框（checkbox）

### 7.3 消息处理（流式 AI 回复）

聊天模式采用流式 AI 回复，使用 `callAiStream()` 函数：

1. 用户发送消息后立即添加到消息列表（`role: 'user'`）
2. 创建一条空消息（`role: 'assistant', content: ''`）并记录其 id
3. 调用 `callAiStream(recentMessages, callbacks)` 发起流式请求
4. 每次收到 `onChunk(text)` 时，调用 `updateMessage(aiMsgId, fullText)` 实时更新气泡内容
5. 流结束后，`onDone(fullText)` 中关闭加载状态；若空则显示错误提示

**上下文构建规则：**
- 取最近 10 条非 system 消息 + 当前用户消息
- 每条消息结构：`{ role: 'user' | 'assistant', content: string }`

**加载状态：**
- `isAiResponding=true` 时，消息列表末尾显示"AI 正在回复..."动画省略号气泡
- 省略号每 500ms 旋转（`·` → `··` → `···` → `    `）

### 7.4 消息右键菜单（删除）

- 对任意消息气泡右键（`onContextMenu`），在鼠标位置弹出浮层菜单
- 菜单显示红色"删除"文字，点击后调用 `deleteMessage(id)` 删除该条消息
- 点击菜单外部自动关闭

### 7.5 切换 API 自动清空

`ConsolePanel` 通过 `useEffect` 监听 `api-connection-store` 的 `selectedApi` 变化：

```typescript
// 切换 API 时自动清空聊天记录（避免前文串模型）
useEffect(() => {
  const unsub = useApiConnectionStore.subscribe((state, prev) => {
    if (state.selectedApi !== prev.selectedApi) {
      useSmartConsoleStore.getState().clearMessages();
    }
  });
  return unsub;
}, []);
```

切换模型后历史消息清零，确保每次对话从白纸开始。

### 7.6 批量删除

右键菜单第二项为"批量删除"，点击后进入批量选择模式：

1. **进入批量模式**：每条消息左侧出现 checkbox，顶部出现操作栏
2. **选择消息**：勾选需要删除的消息（显示"已选 N 条"）
3. **操作按钮**：
   - `取消`：退出批量模式，清空选中
   - `删除选中`：红色按钮，一键删除所有勾选消息
4. **退出时机**：点击取消、删除完成后自动退出

## 10. 数据流展示规范

### 10.1 范围

只展示选中节点及其**直接上下游**：
- 上游：所有 `edge.target === selectedNode.id` 的源节点
- 下游：所有 `edge.source === selectedNode.id` 的目标节点

### 10.2 标签命名

```
📥 text（从上游接收的数据）
📤 aiOutput（AI 处理结果）
```

- **text**：从上游接收传播的文本数据（源节点由调试器写入）
- **aiOutput**：AI 处理后的输出（模板节点无 AI 逻辑则为空/暂无输出）

### 10.3 数据源

| 字段 | 来源 |
|------|------|
| text | `canvas-store.nodes[n].data.text` |
| aiOutput | `canvas-store.nodes[n].data.aiOutput` |
| 面板数据 | `panel-data-store.data[nodeId]` |
| 节点类型 | `canvas-store.nodes[n].type` |

## 13. 注意事项

### 13.1 边界情况

1. **未选中节点（调试模式）**：显示"未选中节点" + "在画布上点击一个节点查看调试信息"
2. **节点无上下游**：显示"该节点无上下游连接"
3. **节点无面板数据**：显示"无面板数据"
4. **无 AI 逻辑的模板节点**：跳过执行，提示"节点为模板节点（无 AI 逻辑）"
5. **world-editor 未打开面板**：执行时提示"请确保已双击打开世界编辑器面板"

### 13.2 数据刷新

调试面板每 500ms 自动刷新（`setInterval`），确保数据最新。

### 13.3 性能考虑

- 面板关闭时完全不渲染（`if (!isOpen) return null`）
- 使用 Zustand 选择器最小化订阅
