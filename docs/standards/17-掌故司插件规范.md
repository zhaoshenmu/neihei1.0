# 掌故司插件规范

> 最后更新: 2026-05-20

## 1. 架构概述

掌故司（zhang-gu-si）是一个**非线性信号灯标签列表节点**，固定 ID 为 `001`。

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| **信号灯** | 每个标签前的圆形指示灯，状态为 `waiting`（灰色）/ `running`（粉色发光）/ `done`（绿色发光） |
| **标签** | 独立的模块标识，系统预设 10 个标签位，目前第 1 个（outline-bind）已激活，其余为预留 |
| **面板** | 双击标签弹出的悬浮窗口，通过 `FloatingContainer` 渲染，不自带关闭按钮 |
| **注册表** | 标签页按需加载的组件映射，每个标签对应独立文件夹 |

### 1.2 架构模型

```
掌故司节点 (index.tsx)
├── 信号灯标签列表
│   ├── ● 大纲锚定绑定模块 (outline-bind)    ← 双击弹出面板
│   ├── ● 预留标签 02 (tab-02)
│   ├── ● 预留标签 03 (tab-03)
│   ├── ...
│   └── ● 预留标签 10 (tab-10)
└── 悬浮面板列表 (FloatingContainer × N)
    ├── 面板 A (双击 outline-bind 创建)
    ├── 面板 B (双击 tab-02 创建)
    └── ...
```

## 2. 标签生命周期

### 2.1 标签定义

标签在 `src/plugins/zhang-gu-si/types.ts` 中定义：

```typescript
// ZhangGuSiTabId 枚举（全英文 kebab-case）
type ZhangGuSiTabId = 'outline-bind' | 'tab-02' | ... | 'tab-10';

// TABS 数组（显示名称用中文）
const TABS: ZhangGuSiTabDef[] = [
  { id: 'outline-bind', label: '大纲锚定绑定模块' },
  { id: 'tab-02',      label: '预留标签 02' },
  ...
];
```

### 2.2 新增标签流程

1. 在 `types.ts` 的 `ZhangGuSiTabId` 中添加新枚举值
2. 在 `TABS` 数组中添加定义
3. 在 `pages/` 下创建 `<new-tab-id>/index.tsx` 组件
4. 在 `pages/page-registry.tsx` 中添加 `lazy(() => import(...))` 映射

### 2.3 信号灯状态

信号灯状态由外部事件驱动（数据流引擎），非顺序流转。

| 状态 | 颜色 | 发光效果 | 含义 |
|------|------|---------|------|
| `waiting` | `#4a4a4a` | 无 | 等待执行 |
| `running` | `#ff69b4` | `0 0 6px rgba(255,105,180,0.6)` | 正在执行 |
| `done` | `#44cc44` | `0 0 6px rgba(68,204,68,0.4)` | 执行完成 |

**常量位置**：`src/constants/index.ts` → `ZHANG_GU_SI.SIGNAL_COLORS` / `ZHANG_GU_SI.SIGNAL_GLOWS`

> ⚠️ 颜色和发光常量统一在 constants 内定义，禁止在 index.tsx 和 Panel.tsx 中重复定义。

## 3. 面板管理规则

### 3.1 打开面板

- 用户双击标签 → `addPanel(tabId)` → 创建 `FloatingContainer`（世界编辑器风格）
- `addPanel` 会检查该 `tabId` 是否已有面板打开，有则跳过不重复创建

### 3.2 关闭面板

- 面板**不自带 ✕ 关闭按钮和标题栏**
- 唯一关闭方式：右键面板 → `ContextMenu` →「关闭面板」（`danger: true`，红色样式）
- 面板关闭后再次双击可重新打开

### 3.3 面板样式

- 宽度：从 `@/constants` 的 `PANEL_WIDTH`（400px）常量引用
- 高度：`PANEL_DEFAULT_HEIGHT`（900px），`PANEL_MIN_HEIGHT`（400px），`PANEL_MAX_HEIGHT`（1200px）
- 节点自身宽度：`PLUGIN_NODE_WIDTH.STANDARD`（260px）/ `PLUGIN_NODE_WIDTH.WIDE`（300px）

### 3.4 同一节点多面板

- 不同标签可并行打开各自面板
- 每个面板独立渲染 `LazyPage` 组件
- 面板关闭事件通过 `onClose` 回调处理

## 5. 数据展示原则：面板只读内核数据

### 5.1 核心原则

每个标签的面板组件**只负责展示内核数据**，不持有、不写入数据。

```
内核数据层（store / dataflow）
  └── 面板组件通过 store 读取数据并渲染 UI
       └── 只做展示，不持有数据
```

### 5.2 规则

| # | 规则 |
|---|------|
| 1 | 面板组件（`pages/<tabId>/index.tsx`）只能从 store 读取数据，不得在组件内定义数据 |
| 2 | 数据由内核管理（`zhang-gu-si.store.ts` 或未来的记忆内核 store），通过 `useZhangGuSiStore` 读取 |
| 3 | 数据变更由外部事件驱动（数据流引擎/其他节点）→ 更新 store → 面板自动响应 |
| 4 | 面板不写数据，只读数据。写入操作由数据流引擎或其他节点完成 |

### 5.3 示例

```typescript
// ✅ 正确：面板只读数据
function OutlineBindPanel() {
  const outlineData = useZhangGuSiStore(s => s.outlineBindData);
  return <div>{outlineData.title}</div>;
}

// ❌ 错误：面板不应直接持有或写入数据
function OutlineBindPanel() {
  const [localData, setLocalData] = useState({...}); // 禁止
  return <div>{localData.title}</div>;
}
```

## 6. 面板生命周期独立规则

### 6.1 核心原则

掌故司面板的渲染必须独立于节点组件，确保节点收起/折叠时面板保持打开。

### 6.2 规则

| # | 规则 |
|---|------|
| 1 | 面板渲染组件（`ZhangGuSiPanels`）必须从节点组件中剥离，作为独立导出 |
| 2 | 面板渲染组件必须在 Canvas 层引用（`Canvas.tsx` 中 `<ZhangGuSiPanels />`），而非在节点组件内部 |
| 3 | 节点组件（`ZhangGuSiNode`）只负责标签列表 UI 和双击触发 `addPanel()`，不渲染任何 `FloatingContainer` |
| 4 | 面板的打开/关闭状态由 `zhang-gu-si.store.ts` 的 `panels` 数组管理，与 React Flow 的节点生命周期解耦 |
| 5 | 面板的唯一关闭方式：右键面板 → ContextMenu →「关闭面板」 |

### 6.3 架构示意

```
Canvas.tsx
├── <ReactFlow>
│   └── <ZhangGuSiNode />        ← 只渲染标签列表，双击触发 addPanel()
├── <ZhangGuSiPanels />          ← 独立于节点，渲染所有 FloatingContainer
│   ├── FloatingContainer (tab-01)
│   ├── FloatingContainer (tab-02)
│   └── ...
└── 其他面板 (renderFloatPanels)
```

### 6.4 代码示例

```typescript
// ✅ 正确：节点组件只负责 UI 和触发
export default function ZhangGuSiNode(_props: NodeProps) {
  const addPanel = useZhangGuSiStore((s) => s.addPanel);
  return <div>{/* 标签列表 */}</div>;
}

// ✅ 正确：面板渲染在 Canvas 层，独立组件
export function ZhangGuSiPanels() {
  const panels = useZhangGuSiStore((s) => s.panels);
  return <>{panels.map(p => <FloatingContainer key={p.id}>...</FloatingContainer>)}</>;
}

// Canvas.tsx 中引用
import { ZhangGuSiPanels } from '@/plugins/zhang-gu-si';
// ...
<ZhangGuSiPanels />
```

## 7. 关键代码规则

| # | 规则 |
|---|------|
| 1 | 节点组件使用 `export default function` 定义（§4.1 规范） |
| 2 | 未使用参数使用 `_` 前缀（如 `_props: NodeProps`），禁止 `void` hack |
| 3 | 禁止 `as any` 类型断言（用具体类型如 `as LazyExoticComponent<FC>` 替代） |
| 4 | 样式常量（信号灯颜色/发光）从 `@/constants` 的 `ZHANG_GU_SI` 引用 |
| 5 | 面板宽度、节点宽度从 `@/constants` 的 `PANEL_WIDTH` / `PLUGIN_NODE_WIDTH` 引用 |
| 6 | manifest.json 的 description 与实际功能一致 |
| 7 | store/utils 必须有对应的测试文件 |
