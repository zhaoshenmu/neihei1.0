## 1. 项目架构与模块划分

### 1.1 目录结构与职责

```
src/
├── components/      # 通用 UI 组件（可引用 store、theme、utils）
├── canvas/          # 画布相关组件与逻辑（引用 store、nodes）
├── nodes/           # 节点渲染组件（NodeRenderer、NodePort、NodeWrapper）
├── store/           # 状态管理（不引用 components！只引用 types、utils）
├── plugins/         # 插件目录（每个插件一个子目录，含 manifest.json）
│   ├── FIXED_IDS.md # 插件 fixedId 注册表（新增插件前必读）
│   ├── world-editor/
│   └── zhang-gu-si/
├── plugin-system/   # 插件框架（加载器、注册表、沙箱、类型定义）
├── dataflow/        # 数据流引擎（数据包、执行引擎、AI 节点执行）
├── runtime/         # Worker 运行时（NodeWorker、WorkerPool）
├── services/        # 服务层（AI 服务等外部服务调用）
├── theme/           # 主题配置
├── types/           # 全局类型定义
├── constants/       # 全局常量
├── utils/           # 通用工具函数
├── hooks/           # 自定义 React Hooks
├── floating/        # 浮动面板组件
├── sidebar/         # 侧边栏组件
└── config/          # 配置文件（JSON schema 等）
```

### 1.2 依赖方向规则（禁止反向依赖）

```
components → store → types/utils
                ↓
            plugin-system → plugins
                ↓
           dataflow → runtime
```

- **`store/`** 不可引用 `components/` 中的内容
- **`utils/`** 不可引用任何 React 相关内容
- **`plugins/`** 内部可引用 `plugin-system/`，但不可反过来
- **`theme/`** 可被任何组件引用

## 2. 文件命名规范

### 2.1 核心规则

| 文件类型 | 命名规则 | 示例 |
|---------|---------|------|
| **React 组件文件** | `PascalCase.tsx` | `TopToolbar.tsx`、`NodePort.tsx` |
| **页面文件** | `PageXxx.tsx` | `PageSetting.tsx`、`PageCharacter.tsx` |
| **工具函数文件** | `kebab-case.ts` | `process-ai-response.ts`、`prompt-template.ts` |
| **类型定义文件** | `kebab-case.ts` | `data-packet.ts`、`plugin-types.ts` |
| **状态管理文件** | `kebab-case-store.ts` | `canvas-store.ts`、`execution-store.ts` |
| **自定义 Hook 文件** | `useXxx.ts` | `useRunHandler.ts` |
| **索引导出文件** | `index.ts` | 每个模块目录下的入口 |
| **配置文件** | `kebab-case` | `eslint.config.js`、`vite.config.ts` |
| **样式文件** | `kebab-case.css` | `App.css` |
| **文档文件** | `XX-中文名.md` | `01-架构总览.md`、`02-代码规范.md` |

### 2.2 禁止规则

- ❌ 禁止使用空格或中文命名文件
- ❌ 禁止使用无意义的简写（如 `utils.ts` 代替 `index.ts`）
- ✅ 文件名应与导出的主要内容一一对应

## 3. 代码命名规范（TypeScript）

### 3.1 通用规则

| 类型 | 规则 | 示例 |
|------|------|------|
| **变量** | `camelCase` | `pluginLoaded`, `runState`, `btnBase` |
| **函数** | `camelCase` | `generateNodeId()`, `handleRun()` |
| **布尔值** | `is`/`has`/`should`/`can` 前缀 | `isRunning`, `canUndo`, `hasCycle()` |
| **常量（模块级）** | `camelCase` | `btnBase`, `consoleCaptureRef` |
| **常量（魔术数字/字符串）** | `UPPER_SNAKE_CASE` | `STYLE_PRESETS`, `WORLD_RULE_PRESETS` |
| **私有/内部函数** | 无特殊前缀，按 `camelCase` | `generateNodeId()`（模块内不导出即可） |
| **参数** | `camelCase` | `nodeId: string`, `position: XYPosition` |

### 3.2 接口与类型

| 类型 | 规则 | 正确示例 | 错误示例 |
|------|------|----------|----------|
| **接口** | `PascalCase`，**不加 I 前缀** | `PluginManifest`, `CanvasState` | `IPluginManifest` ❌ |
| **类型别名** | `PascalCase` | `NodeExecStatus`, `VaultTab` | |
| **枚举成员** | `PascalCase` | `'idle' \| 'running'` | `'IDLE'` ❌ |
| **Props 接口** | `ComponentName + Props` | `TopToolbarProps` | |

### 3.3 Store 命名

```typescript
// ✅ 正确
export const useCanvasStore = create<CanvasState>()(...);

// 接口统一叫 XxxState（而不是 XxxStore）
export interface CanvasState {
  nodes: Node[];
  ...
}
```

### 3.4 React 组件 Props

```typescript
// ✅ Props 接口名 = 组件名 + Props
interface TopToolbarProps {
  onRun?: () => void;
  runState?: 'idle' | 'running';
}

// ✅ 回调 Props 用 on 前缀
onRun, onNodesChange, onConnect, onClose

// ✅ 事件处理函数用 handle 前缀
handleRun, handleNew, handleStyleSelect, handleWorldRuleConfirm
```

### 3.5 类型安全 —— 禁止 any

```typescript
// ❌ 禁止
const setVal = (key: string, val: any) => updateNodeData(nodeId, key, val);

// ✅ 正确做法：使用泛型或明确类型
const setVal = (key: string, val: unknown) => updateNodeData(nodeId, key, val);
// 或定义具体的联合类型
type SettingField = 'creativeIdea' | 'perspective' | 'style';
const setVal = (key: SettingField, val: string) => updateNodeData(nodeId, key, val);
```

## 4. 组件设计规范

### 4.1 组件定义方式

**统一使用 `export default function Xxx()` 方式：**

```tsx
// ✅ 统一标准
interface Props {
  nodeId: string;
}

export default function PageSetting({ nodeId }: Props) {
  // ...
}
```

### 4.2 组件文件结构

```
1. 文件头 JSDoc 注释
2. import 语句（先外部库，后内部模块）
3. Props 接口定义
4. 组件函数（export default）
5. 辅助子组件（不用 export，无 default）
```

### 4.3 组件职责

- 每个组件只做一件事
- 页面组件（`pages/`）：负责数据获取和布局
- 通用组件（`components/`）：负责 UI 呈现，通过 Props 接收数据
- 一个文件一个主要导出组件

### 4.4 Hook 使用规范

```typescript
// ✅ useEffect 的依赖数组必须显式列出所有依赖
useEffect(() => {
  useSettingsStore.getState().loadSettings();
}, []); // 只有初始化才用空数组

// ✅ useCallback 用于传递给子组件的回调
const onRunClick = useCallback(() => {
  handleRun();
}, [handleRun]);

// ✅ 状态提升：多个组件共享的状态放到 store
// ❌ 禁止：用 props drilling 传递超过 3 层
```

## 5. 状态管理规范（Zustand）

### 5.1 Store 创建模板

```typescript
/**
 * xxx-store.ts
 *
 * 职责描述
 */

import { create } from 'zustand';
import { persist } from 'zustand/middleware';

export interface XxxState {
  /** 状态字段，必须标注 JSDoc */
  data: Record<string, string>;

  // 操作方法
  setData: (key: string, value: string) => void;
  resetAll: () => void;
}

export const useXxxStore = create<XxxState>()(
  persist(
    (set, get) => ({
      data: {},

      setData: (key: string, value: string) => {
        set((state) => ({
          data: { ...state.data, [key]: value },
        }));
      },

      resetAll: () => {
        set({ data: {} });
      },
    }),
    {
      name: 'neihei-xxx',       // localStorage 键名，统一 neihei- 前缀
      partialize: (state) => ({  // 只持久化必要字段
        data: state.data,
      }),
    }
  )
);
```

### 5.2 Store 命名规范

- 接口名：`XxxState` ✅（不用 `XxxStore`）
- Store 变量名：`useXxxStore` ✅
- 文件名：`xxx-store.ts` ✅
- 统一在 `store/index.ts` 中导出

### 5.3 Store 行为规范

```typescript
// ✅ Component 中读取 Zustand store
const nodes = useCanvasStore((s) => s.nodes);

// ✅ 跨 Store 引用（在 action 方法中使用 getState）
useUndoStore.getState().snapshot();

// ❌ 禁止在 action 外通过 getState() 修改 store（应通过 action）
```

### 5.4 冗余方法禁止

```typescript
// ❌ 禁止：Zustand 本身就支持直接读取，不需要包装
getNodeState: (nodeId: string) => {
  return get().states[nodeId];
}

// ✅ 外部直接读
const state = useExecutionStore((s) => s.states['n_xxx']);
```

## 6. 样式与主题规范

### 6.1 主题系统

```typescript
// ✅ 所有颜色/字体/间距从 theme 对象引用
import { theme } from '@/theme/neihei-theme';

<div style={{ background: theme.colors.canvasBg }}>
```

### 6.2 颜色体系（固定值）

| 用途 | 色值 | 变量名 |
|------|------|--------|
| 面板背景 | `#0d0d0d` | `sidebarBg`, `nodeBg`, `buttonBg` |
| 画布背景 | `#141414` | `canvasBg` |
| 边框/分割线 | `#1e1e1e` | `nodeBorder`, `inputBorder` |
| 主要文字 | `#e0e0e0` | `textPrimary` |
| 次要文字 | `#b0b0b0` | `textSecondary` |
| 弱化文字 | `#808080` | `textMuted` |
| 选中/高亮 | `#6a9fb5` | 端口、节点选中边框 |

### 6.3 内联样式 vs CSS 类

- **统一使用内联 `style={}` + theme 引用**（当前项目的主要方式）
- 仅在**全局样式重置**或**动画关键帧**等场景使用 `.css` 文件
- 不要在 `.css` 文件中定义主题相关的颜色值

### 6.4 组件内局部样式常量

当一个组件需要复用的样式对象时，在文件内定义：

```typescript
const btnBase: React.CSSProperties = {
  background: 'transparent',
  border: 'none',
  color: theme.colors.textSecondary,
  padding: '6px 14px',
  fontSize: 13,
};
```

## 7. 注释与文档规范

### 7.1 文件头注释

每个文件顶部必须包含 JSDoc 注释，按需包含以下内容：

```typescript
/**
 * 文件名
 *
 * 功能描述（一句话）
 *
 * 布局说明（如果是组件，用 ASCII 图或文字说明，可选）
 * 职责描述（可选）
 * 设计原则（可选）
 */
```

### 7.2 函数/接口注释

```typescript
/** 生成唯一的节点 ID */
function generateNodeId(): string { ... }

/** 插件节点的运行时定义 */
export interface PluginNodeDefinition {
  manifest: PluginManifest;
  component: React.ComponentType<NodeProps>;
  panel?: React.ComponentType<{ nodeId: string }>;
}
```

### 7.3 关键逻辑标记

使用 `🔒` 标记关键/敏感逻辑，方便代码审查：

```typescript
// 🔒 P0-2：初始化数据流引擎，订阅节点变化自动传播 AI 数据
initDataflowEngine();

// 🔒 P1-1：操作前快照（撤销/重做）
useUndoStore.getState().snapshot();

// 🔒 P1-3：连线规则校验（禁止自连接、重复边、循环依赖）
```

优先级标记：
- `P0`：核心功能，不可出错
- `P1`：重要功能，需注意
- `P2`：优化/次要功能

### 7.4 右键菜单/浮层规范

右键菜单使用固定定位 `position: fixed`，在鼠标位置弹出：

```typescript
const [showMenu, setShowMenu] = useState(false);
const [menuPos, setMenuPos] = useState({ x: 0, y: 0 });
const menuRef = useRef<HTMLDivElement>(null);

const handleContextMenu = useCallback((e: React.MouseEvent) => {
  e.preventDefault();
  setMenuPos({ x: e.clientX, y: e.clientY });
  setShowMenu(true);
}, []);

// 点击菜单外部自动关闭
useEffect(() => {
  if (!showMenu) return;
  const handler = (e: MouseEvent) => {
    if (menuRef.current && !menuRef.current.contains(e.target as Node)) {
      setShowMenu(false);
    }
  };
  document.addEventListener('mousedown', handler);
  return () => document.removeEventListener('mousedown', handler);
}, [showMenu]);
```

- 危险操作（删除）使用红色字体 `#ff6b6b`
- 分隔线使用 `div` 元素，高度 1px，背景 `rgba(255,255,255,0.08)`
- 最小宽度至少 100-120px

### 7.5 批量选择模式规范

当需要多选操作时：

1. **进入方式**：右键菜单第二项触发，或按钮触发
2. **状态管理**：`batchMode: boolean` + `selectedIds: Set<string>` 在组件内用 `useState` 管理
3. **操作栏**：浮动在列表区域外部（使用 Fragment `<>`），**不随滚动条滚动**
4. **操作栏内容**：显示"已选 N 条" + 取消按钮 + 操作按钮
5. **危险操作（删除）**：按钮背景 `#ff6b6b`，禁用时半透明
6. **退出时机**：取消、操作完成后自动退出

## 8. ESLint & Prettier 配置规范

### 8.1 已有规则（必须遵守）

| 规则 | 级别 | 说明 |
|------|------|------|
| `no-var` | error | 禁止使用 var，用 const/let |
| `eqeqeq` | warn | 必须用 === 和 !== |
| `curly` | warn | 所有控制语句必须用 {} |
| `prefer-const` | warn | 不重新赋值的变量用 const |
| `@typescript-eslint/no-explicit-any` | warn | **尽量不用 any** |
| `@typescript-eslint/consistent-type-imports` | warn | 类型导入用 `import type { ... }` |

### 8.2 约束汇总

```typescript
// ✅ 允许
console.log()              // 项目内 console 用于日志系统
import type { Node }       // 类型导入使用 type 关键字

// ❌ 禁止
var x = 5;                 // 用 const / let 代替
x == null                  // 用 x === null || x === undefined
if (x) doSomething()       // 必须用 { }
```

## 9. Git 提交规范

### 9.1 Commit Message 格式

```
<type>(<scope>): <description>

[optional body]
```

### 9.2 type 类型

| type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 重构 |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响功能） |
| `chore` | 构建/工具链变更 |
| `test` | 测试变更 |

### 9.3 示例


## 10. 错误处理规范

### 10.1 日志记录

```typescript
// ✅ 将错误写入 LogStore（用户可见）
useLogStore.getState().addLog({
  type: 'error',
  message: '插件加载失败',
  detail: error.message,

// ✅ 控制台日志用于开发调试
```

### 10.2 try-catch 使用场景

- **异步操作**（AI 调用、文件读写）必须 try-catch
- **插件加载**必须 try-catch
- **同步计算**推荐用返回 Result 类型而非抛异常

## 11. 安全规范

### 11.1 插件执行

- 插件代码在 **WebWorker 沙箱**中执行
- 插件不可直接访问 DOM
- 插件返回的数据必须是纯 JSON

### 11.2 数据校验

- 从 Worker 接收的数据必须校验格式
- 用户输入（如"风格展开描述"）不做 HTML 转义（纯文本环境）

## 12. 性能规范

### 12.1 React 渲染优化

```typescript
// ✅ 大数据列表使用 useMemo
const nodeList = useMemo(() => 
  nodes.map(n => ({ id: n.id, label: n.data.label })),
  [nodes]
);

// ✅ 传递给子组件的回调使用 useCallback
const handleClick = useCallback(() => {
  onNodeClick(nodeId);
}, [nodeId, onNodeClick]);

// ✅ Store 订阅最小化（只订阅需要的字段）
const nodeCount = useCanvasStore((s) => s.nodes.length);
// ❌ 禁止：const canvasStore = useCanvasStore(); // 订阅了整个 store
```

### 12.2 画布优化

- 避免在画布节点渲染中执行繁重计算
- 节点的数据更新通过 `dataVersion` 计数器触发
